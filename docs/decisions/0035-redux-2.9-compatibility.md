# Decision 0035: Redux 2.9 compatibility

The maintainer requested Redux 2.9 support alongside 2.8.5 for this beta.
The two explicit targets are Redux 0.2.8.5.103184 / Unity 6000.4.1f1 and
Redux 0.2.9.0.104521 (26w36c) / Unity 6000.5.8f1, Windows x64 / D3D11.

The managed assembly and Addressables bundle continue to use the pinned 6.4.1
SDK build. Runtime validation covers loading that payload on both players.
Do not import a mixture of the two players' managed assemblies into the Editor.

## Version-sensitive boundaries

- Official Built-in `Internal-MotionVectors.shader` sources in 6.4.1 and 6.5.8
  have the identical SHA-256
  `7843659981e088c0500896433f779903bc3297ef40abec2d2f91a550b54bef64`.
  The existing narrow identity-history repair can use the same shader. Its
  runtime gate accepts only these exact versions. Future Unity versions fail
  closed for this optional repair.
- Cecil inspection confirms the nine-argument
  `VegetationSystemPro.RenderVegetationItemLODIndirect` signature is unchanged.
  The runtime patch still checks that exact signature and its integer buffer IDs.
- `VolumeCloudRenderer.RenderClouds()` and observed integer size fields are
  unchanged. The optional observer remains guarded before Harmony installation.
- Load-success, revert-complete and vessel-change message types remain available.
- NVIDIA/AMD managed feature creation and execution surfaces remain compatible;
  the existing cached delegates retain their optional-module behavior.
- The test harness's camera API changed. Rebuild it against the selected player;
  do not reuse the 2.8.5 harness binary on 2.9. The runner does this automatically.

## Runtime bundles

Use separate **redux2.8.5** and **redux2.9** full ZIPs. Each contains its exact
Unity player version's three optional native runtime files. A shared managed
payload does not imply interchangeable native DLLs. The packager defaults to
2.9 and accepts `-ReduxTarget 2.8.5` for the earlier player. Redux itself remains
user-installed and excluded from every package.
