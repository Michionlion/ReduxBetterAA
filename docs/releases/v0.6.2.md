Better AA 0.6.2 starts new installations with custom TAA (shown as **TAA**).
Updates preserve saved mode selections, including Off. Invalid or unavailable
modes still fall back to Off.

Since v0.6.1:

- Restore coherent map jitter and draw map icons after AA so icons remain sharp.
- Consolidate backend state, mode persistence and texture setup without changing
  the temporal resolve algorithms or their default quality settings.
- Release partially created TAA textures on allocation failure.
- Use the actual report camera for motion diagnostics and preserve camera depth
  flags changed by another owner when closing a buffer view.
- Simplify fresh-checkout builds and add an isolated release candidate pipeline,
  including a first-install TAA check before any test changes the selected mode.

Extract `ReduxBetterAA-0.6.2.zip` beside `KSP2_x64.exe`. For DLAA or FSR 2,
also extract the runtime ZIP matching your Redux version. Custom TAA and
spatial modes require no extra native libraries.

This remains a beta for Windows x64 and Redux 0.2.8.5/0.2.9.0. Supersampling
falls back to Off in the map and main menu. Stop F10's live A/B comparison before
judging terrain stability or performance. Other GPUs, long sessions and the
full range of flight/VAB scenes need broader testing. There is no DLSS upscaling
or frame generation.

Release validation must include the [standard checks](../../tests/README.md).
The candidate pipeline retains exact source and runtime hashes, test results,
diagnostic reports and screenshots outside the source checkout. Moving-image
review and performance results must identify their tested setup; automated
capture checks alone do not certify either.
